# FitOS

FitOS 是一款中文、本地优先的个人健身管理网站。默认使用浏览器 IndexedDB；需要跨设备时可选配置独立 Supabase 项目，不依赖云服务也能使用本地功能。

## 已实现

- 个人档案、健身目标、身体指标记录与输入校验。
- 商业健身房动作库（23 个常见动作）和筛选搜索。
- 训练计划、动作选择、训练执行、组记录、组间休息计时、训练暂停/恢复、历史快照。
- 常见食物库（内置食物可编辑）、每日餐食记录、营养目标、饮水目标与逐次饮水记录；营养看板醒目展示目标、完成率和正负差额。
- 动作库内置动作和用户动作均可新增、编辑和删除；历史训练使用快照，不随动作库编辑变化。
- 可新增身体自定义指标和每日手动营养指标及目标，查看当天完成量与差额。
- 身体趋势、周训练次数、训练容量、已记录饮食的平均摄入。
- 多服务商兼容 OpenAI Chat Completions API 的浏览器直连、连接测试和建议生成。
- IndexedDB JSON 备份恢复、合并导入、CSV 导出、面向 AI 分析的体重与完整饮食 Markdown 报告、清空数据确认。
- 可选 Supabase 私有账户自动同步：登录后读取云端最新快照，本地数据保存后自动上传；本地 IndexedDB 仍是默认存储。
- 响应式手机和桌面 UI、主题切换和基础 PWA 离线壳。

## 运行

该版本是无构建步骤的静态 Web 应用。浏览器模块、IndexedDB 与 Service Worker 应通过 localhost 或 HTTPS 访问。

```powershell
node serve.mjs
```

打开 <http://localhost:4173>。要从手机临时访问，电脑和手机需在同一 Wi-Fi，然后在启动窗口使用输出的局域网地址（`http://电脑IPv4:4173/`）。也可以使用任意静态文件服务器托管当前目录。运行核心计算检查：

```powershell
node --test calculations.test.js
node --check app.js
```

## AI 配置

打开“AI 私人教练”，填写服务商 Base URL（例如兼容 `/v1/chat/completions` 的 API 根地址）和模型名，再输入 API Key。连接测试或本次标签页会话中，密钥只保存在 `sessionStorage`；关闭标签页后会清除。供应商配置保存在 IndexedDB，但不含密钥。浏览器直连会使密钥暴露于当前浏览器环境，且供应商可能因 CORS 拒绝请求。AI 调用只在用户主动点击后发送必要上下文。AI 输出是建议，需自行核对。

## 数据与隐私

默认数据保存在当前浏览器的 IndexedDB。可选 Supabase 自动同步必须自行配置项目、执行 RLS SQL 并登录同一账号；登录或重新打开应用时下载云端快照，本地修改保存后自动上传。离线修改会在联网后重试；多个设备同时编辑时采用整份快照同步，不能做字段级冲突合并。定期导出 JSON。AI Key 不在 JSON 或云端业务快照中。登录会话保存在浏览器本地，退出登录或清理浏览器数据后需重新登录；请勿在共用设备保持登录。

## 备份恢复与 CSV

设置中可导出完整 JSON；恢复前检查版本和结构，可选择完全恢复或按稳定 ID 合并。Markdown AI 分析报告包括全部已记录体重、每日逐餐食物和营养汇总。CSV 导出包含身体记录、训练历史、训练组明细、饮食明细或每日营养汇总，使用 UTF-8 BOM 以兼容中文 Excel。完全恢复和清空数据前会二次确认。云同步配置步骤见 [SUPABASE_SYNC.md](SUPABASE_SYNC.md)。

## 静态部署

将此目录作为静态网站发布到支持 HTTPS 的托管服务。无需数据库和构建命令。首次上线前在目标域名检查 IndexedDB、PWA 安装及静态资源路径。浏览器直连 AI 依赖服务商 CORS 设置。项目不包含可公开部署的 AI 密钥代理；不要把私人密钥写进前端源码。

## 当前限制

- 网页是纯静态应用。云同步需用户自备 Supabase 项目；同步是手动全量快照覆盖，不提供实时同步和冲突合并。
- 尚无 Playwright 端到端流程或服务端 AI 代理。
- 训练日编辑支持动作增删，但第一版尚未提供拖动排序、独立多个训练日模板和个人最佳提示。
- 训练历史保存完成组及计划快照；休息倒计时、照片、恢复日志、周期复盘和高级食谱管理尚未实现。
- BMI 仅作粗略估算；本版本未自动推算 BMR/TDEE 或医学建议。
- 动作和食物营养数据仅用于一般记录，个别食材数值可能受品种与加工方式影响，包装食品请以标签为准。

## 新增：照片识别、份量快捷记录与体态照

- 饮食页的“拍照识别并记录”需要支持视觉输入的 Chat Completions 模型。DeepSeek 当前文档列出的视觉模型为 `deepseek-flash`；兼容服务商和模型能力以各服务商文档为准。照片与请求内容会发送到你配置的服务商，AI 结果需要核对确认后才写入饮食记录。
- AI API Key 在当前设备浏览器本地保存，换设备要重新配置一次；它不会同步到 Supabase 或 JSON 数据备份。浏览器本地保存不能防止设备上的其他使用者、扩展或恶意脚本读取。
- 食物可在食物库编辑常用分量，每行填写“名称=克数”，例如 `1个鸡蛋=50`；新增饮食时可按份量快速选取。
- 动作库可导入 Free Exercise DB 开放动作数据（含动作步骤和参考图片链接）。数据集使用 Unlicense；图片来自上游仓库，需要联网加载。见 [Free Exercise DB](https://github.com/yuhonas/free-exercise-db)。
- 体态照片压缩后仅保存在本设备 IndexedDB，不上传 AI 或 Supabase；完整 JSON 备份会包含照片，文件可能较大。
